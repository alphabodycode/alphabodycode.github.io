# AlphaBodyCode 营养记录器 — 公开测试版 v0.1.0

## 适用范围与前置条件

仅可操作用户拥有、且已明确打开或授权使用的工作簿。本 Skill **仅包含操作指引**；它本身不会自动连接 Excel、获取 WHOOP 数据、调用营养数据库 API，也不会直接执行电子表格写入操作。在声称某条记录已保存之前，必须使用当前可用的电子表格编辑工具，并核实实际修改的单元格。如果当前没有可用的编辑能力，应返回结构化、可供导入的记录草稿，不得声称已经成功写入。

不得假定用户的工作簿与某一个特定的 AlphaBodyCode 私有文件完全相同。操作前，必须先检查工作表名称、字段映射、计量单位、数据验证规则、公式、表格及命名范围等实际结构。任何结构性修改都必须事先征得用户同意，并在备份副本上进行。

## 工作流程

1. **解析用户请求。** 提取实际日期、时间（允许未知）、食物或原料、数量、单位、品牌、制作方式，以及用户希望执行的是记录饮食、查询营养数据，还是保存配方。使用用户明确指定的日期；如果日期存在歧义，不得自行推断。

2. **先匹配，再新增。** 搜索工作簿中的食物库及其别名。匹配时核对具体品牌、食物状态和计量单位。不得在未说明的情况下，将生食与熟食、不同补剂产品，或即食燕麦片与燕麦粉视为同一种食物。

3. **查询缺失的食物数据。** 对有品牌的食品和补剂，优先使用制造商提供的营养标签；其他情况使用来源可靠、出处可追溯的权威食物成分数据。记录数据来源，并注明数值属于直接读取、推导计算还是估算。如果无法进行实时核实，必须明确告知用户。未知数值不等于零。只在缺少必要信息时向用户询问。

4. **规划工作簿修改。** 新增食物库条目之前，先展示其计量单位、参考份量、营养成分、数据来源、已核实或估算状态，以及重复条目检查结果。对于尚未核实的新条目，必须先获得用户批准才能添加。对于数据明确且已获授权的常规食物记录，可以批量写入。

5. **记录饮食。** 以追加新行的方式写入记录，不得覆盖已有记录。根据日期、时间、食物名称和数量检查可能重复的记录。保留原有公式、下拉列表和格式，并核实查找结果、每日汇总及营养完整性检查是否正确更新。只有在能够明确确认该营养数值为零时，才可以记录为零。

6. **创建一次性配方。** 对临时饮品或混合餐食，创建唯一记录，并逐项记录原料及其用量。按照每种原料的实际数量、单位换算和食用份量计算营养总量。将完整配方作为一条饮食记录写入，不得再把其中的原料分别重复计入。保存带日期的配方组成和营养数据快照，以确保历史记录保持稳定。

7. **仅在用户提出要求时发布固定配方。** 为固定配方分配稳定的 ID 和版本号（V1、V2……）。不得直接修改已经发布或已锁定历史记录的版本；应复制为新版本，再在新版本中修改。核实新版本的配方营养总量，以及历史记录引用的版本是否正确。

8. **记录运动和可穿戴设备估算值。** 每一场运动单独记录一行；同一天的多场训练按日期汇总。将可穿戴设备估算的全天总能量消耗单独记录。每日估算能量差值 = 食物摄入能量 − 可穿戴设备估算的全天总能量消耗。**不得再次扣除运动消耗的卡路里。** 必须区分仅有部分时段数据、数据缺失和记录不完整等不同状态。

9. **验证并汇报。** 对比修改前后的记录数量，检查新增或修改的行，检查查找引用是否失效、公式是否报错，并明确指出尚未核实的结果。简明汇报实际完成写入的内容、仍待用户确认的事项，以及营养看板和能量收支计算是否已刷新。

## 不可妥协的数据保护规则

- 保护用户的私人营养、医疗及运动记录。未经用户明确许可，不得将任何用户的工作簿、真实记录或专有产品标签发布到公开代码仓库。
- 营养摄入量不等于人体实际吸收量，也不等于血液检测结果。可穿戴设备显示的卡路里属于估算值；不得据此宣称能够精确确定能量缺口、脂肪减少量、疾病预防效果或作出疾病诊断。
- 如果发现补剂产品之间可能存在成分重叠，或剂量明显偏高，应提示用户寻求专业评估，不得自行作出诊断。
- 不得编造数据来源、记录、已完成的操作、成功的写入、设备连接状态或工作簿支持的功能。
- 如果工作簿的实际结构与本 Skill 的操作要求不兼容，应停止修改，并先向用户解释建议采用的安全迁移方案。

## 示例指令

- “记录11月2日早餐：贝果1个，牛油果90克，咖啡250毫升。”
- “新增蒸南瓜到食物库，先展示数据来源和每100克的营养数据。”
- “今天11点喝了牛奶250毫升、蛋白粉10克、胶原蛋白5克和抹茶3克，请作为一次性饮品记录。”
- “把刚才的饮品保存为抹茶拿铁V1；不要修改V1的历史数据。”
- “今天有两场运动，分别为45分钟和30分钟。WHOOP显示全天估算消耗为2100千卡，请检查当天的能量收支。”
